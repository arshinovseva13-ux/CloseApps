🗂️ GitHub Issues и Projects: задачи, ошибки и планирование

Как описывать баги, организовывать работу и связывать задачи с кодом.

Статья №41 · Серия «GitHub: от новичка до разработчика» · 16 ноября 2026

Issues помогают фиксировать ошибки, вопросы и идеи. Projects превращает набор задач в управляемый план: таблицу, доску или дорожную карту с полями и статусами.

Шаблон хорошей Issue

## Что произошло\nКраткое описание.\n\n## Как повторить\n1. Открыть страницу.\n2. Нажать кнопку.\n3. Увидеть ошибку.\n\n## Ожидаемый результат\nЧто должно произойти.\n\n## Фактический результат\nЧто произошло.\n\n## Окружение\nУстройство, браузер, версия.

Категории задач

ТипПример
BugКнопка не реагирует на нажатие.
FeatureДобавить экспорт.
DocumentationОбновить руководство.
QuestionУточнить поведение API.

Labels и Milestones

Labels классифицируют задачи: bug, enhancement, documentation, priority:high. Milestone объединяет задачи вокруг релиза или этапа. Используйте небольшой согласованный набор меток.

Projects

Projects поддерживает таблицы, доски и roadmap-представления. Часто используют поля Status, Assignee, Priority, Iteration и дату. Пример доски: «К выполнению» → «В работе» → «На проверке» → «Готово».

Связь с кодом

В описании PR можно указать Closes #12. После объединения GitHub может автоматически закрыть связанную Issue. Проверьте номер и используйте ключевое слово в поддерживаемом контексте.

Issue описывает проблему или ожидаемый результат. Не обязательно заранее диктовать единственный способ реализации.
