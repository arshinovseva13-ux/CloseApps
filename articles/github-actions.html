⚙️ GitHub Actions: автоматизация сборки, тестов и публикации

Основы workflow, events, jobs, steps, runners и безопасного CI/CD.

Статья №43 · Серия «GitHub: от новичка до разработчика» · 16 ноября 2026

GitHub Actions автоматизирует задачи проекта: тесты, сборку, проверку стиля кода, выпуск релизов и публикацию сайта. Сценарии описываются в YAML-файлах.

Основные понятия

ЭлементНазначение
WorkflowАвтоматизированный сценарий.
EventСобытие запуска: push, pull_request, schedule.
JobГруппа шагов, выполняемых на runner.
StepКоманда или готовое action.
RunnerСреда выполнения.
ArtifactСохранённый результат workflow.

Где лежат сценарии

Workflow-файлы хранятся в .github/workflows/. Например, файл checks.yml может запускать проверки при каждом push и Pull Request.

Минимальный пример

name: Basic checks\n\non:\n  push:\n    branches: [main]\n  pull_request:\n\njobs:\n  inspect:\n    runs-on: ubuntu-latest\n    steps:\n      - name: Get source\n        uses: actions/checkout@v4\n      - name: List files\n        run: ls -la

Это учебный пример: он получает код и выводит список файлов. В реальном проекте добавьте установку зависимостей, тесты и сборку. Версии используемых actions периодически проверяйте и обновляйте.

CI и CD

  • CI — автоматические проверки изменений: тесты, линтеры и сборка.
  • CD — подготовка или автоматическая публикация проверенной версии.

Секреты и права

Не вписывайте токены и пароли прямо в YAML. Используйте Actions secrets, ограничивайте permissions минимально необходимыми и не выводите секретные значения в логи. Для сторонних actions оценивайте источник и доверие.

Поиск ошибок

Откройте вкладку Actions, выберите запуск, затем job и упавший step. Найдите первую содержательную ошибку, проверьте пути, версии и переменные окружения. Перед публикацией логов убедитесь, что в них нет секретов.

Надёжный workflow воспроизводим, имеет минимальные права и проверяет результат до публикации.
