🔀 Pull Requests: проверка и объединение изменений

Как открыть PR, пройти code review и выбрать способ merge.

Статья №40 · Серия «GitHub: от новичка до разработчика» · 16 ноября 2026

Pull Request (PR) — предложение перенести изменения из одной ветки в другую. В PR собраны коммиты, описание, обсуждение, ревью и автоматические проверки.

Этапы PR

Создать ветку
↓
Сделать коммиты
↓
Открыть Pull Request
↓
Review и CI-проверки
↓
Исправить замечания
↓
Merge

Что написать в описании

  • Что изменено и зачем.
  • Как проверить результат.
  • Какие известные ограничения остались.
  • Скриншоты, если изменился интерфейс.
  • Ссылка на связанную Issue.

Code review

Ревьюер проверяет логику, читаемость, безопасность, совместимость и соответствие задаче. Комментарии бывают общими и привязанными к строкам. Автор отвечает, вносит правки и отправляет новые коммиты в ту же ветку — PR обновляется.

Варианты объединения

МетодЧто происходит
Merge commitСохраняет историю ветки и добавляет merge-коммит.
Squash and mergeОбъединяет изменения PR в один коммит.
Rebase and mergeПереносит коммиты на вершину базовой ветки.

Draft PR

Черновой PR позволяет показать незавершённую работу, получить раннюю обратную связь и запустить проверки. Его переводят в готовый статус, когда автор считает изменения подготовленными к ревью.

Открытый PR ещё не означает, что изменения попали в основную ветку. Это предложение, которое проходит выбранный процесс проверки.
