🌐 GitHub Pages: бесплатная публикация сайта из репозитория

Как опубликовать статический сайт, настроить источник и исправить 404.

Статья №42 · Серия «GitHub: от новичка до разработчика» · 16 ноября 2026

GitHub Pages публикует статические сайты из репозитория. Он подходит для HTML, CSS, JavaScript и документации, которую можно подготовить как набор статических файлов. Это не обычный сервер для постоянного выполнения backend-кода.

Подготовка

my-site/\n├── index.html\n├── styles.css\n└── script.js

Файл index.html обычно является точкой входа. Проверьте относительные пути: проектный сайт часто находится в подпапке домена, поэтому абсолютный путь /assets/app.css может вести не туда.

Настройка Pages

  1. Откройте Settings → Pages.
  2. В Build and deployment выберите источник.
  3. Для простого сайта можно выбрать Deploy from a branch.
  4. Укажите ветку и каталог, например main и /(root) или /docs.
  5. Сохраните настройки и дождитесь публикации.

Адрес

Проектный сайт обычно имеет адрес вида https://username.github.io/project-name/. Пользовательский сайт аккаунта использует отдельный формат URL. Учитывайте регистр букв в именах файлов и каталогов.

GitHub Actions

Если сайт требует сборки, можно выбрать GitHub Actions и настроить workflow: установка зависимостей → сборка → публикация артефакта. Команды зависят от используемого инструментария.

Диагностика

ПроблемаЧто проверить
404Имя файла, путь, ветку и папку публикации.
Нет стилейОтносительные пути и регистр букв.
Старая версияСтатус deployment и кэш браузера.
Пустая страницаОшибки JavaScript и наличие index.html.
Публикуется содержимое выбранного источника. Не помещайте в публичный репозиторий секреты и приватные данные.
